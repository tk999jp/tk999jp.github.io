MidFD / Design Notes

FDを再現しない。

MidFDを作りながら考えた、FD系ファイラーの操作思想と、その現代的な再定義についての開発者ノートです。

この文書の立場

FD作者自身の意図や思想を代弁するものではありません。FD系ファイラーを使い、MidFDを設計する開発者として、どこに価値を感じ、何を現在のWindowsへ残そうとしているかを記録します。

古いUIを復刻することが目的ではない

昔の見た目や制約をそのまま再現するだけなら、現在のWindowsで使う理由は薄くなります。MidFDが残したいのは、操作対象を明示し、キーボードから直接コマンドへ到達し、習熟によって反復作業を短くできるという感覚です。

Keyboard First

画面上の操作を探してから実行するのではなく、覚えた操作へ直接到達できること。

Mark

一時的なSelectionだけでなく、操作したい対象を明示して扱うという考え方。

Learned Speed

最初からすべてが見えることより、使い込むほど手数が減っていくこと。

Modern Context

タブ、Viewer、現在のWindowsパスやストレージなど、今の環境に必要なものは別途取り込むこと。

残すもの、捨てるもの、加えるもの

KEEP

操作の距離を短くする

キーボード主体のコマンド到達、Markによる対象指定、反復作業を短くする習熟性は残したい部分です。

DROP

当時の制約そのもの

DOS時代の画面やストレージ制約、古い環境に由来する不便さまで保存することは目的にしません。

ADD

現在の作業文脈

タブ、マウス、Viewer、現代的なパスやファイル環境など、現在のWindowsで自然に必要になる要素を取り込みます。

Explorerを否定するためではない

Explorerは、対象を見つけて直感的に操作することに強いUIです。FD系の操作は、その逆として「覚える代わりに、繰り返す操作の距離を短くする」方向に強みがあります。

MidFDはExplorerを置き換える唯一の正解を目指すのではなく、キーボード中心で大量のファイル操作を繰り返すときの、別の最適化を現在のWindowsへ残すことを目指します。

Explorer的発見しやすい / GUI中心 / 初見に強い
FD / MidFD的覚えて速くなる / Keyboard中心 / 反復に強い

MidFDでの再定義

MidFDはFDの完全互換を目標にはしていません。FD系の操作から得た価値を抽出し、現在のWindows上で実際に使える形へ組み直すことを目指します。

今後このDesign Notesでは、Mark、Command、Viewer、タブなどを個別に取り上げ、なぜその形にしたのかを整理します。
